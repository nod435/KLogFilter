KLogFilter 사용 가이드

대상 버전: 1.39 · Android logcat 로그를 실시간으로 받거나 파일로 열어 필터·검색·북마크하고, 장치 CPU·메모리·온도 통계를 엑셀로 남기는 Java Swing 도구. 그림의 검정 번호는 아래 번호 설명과 짝을 이룹니다.

1. 시작하기

필요한 것

  • JDK 또는 JRE 8 이상. 외부 라이브러리는 필요 없습니다.
  • 실시간 수집(Run)과 장치 통계를 쓰려면 adb가 PATH에 있어야 합니다. 저장된 로그 파일만 보려면 adb는 없어도 됩니다.

실행

dist\KLogFilter.bat [로그파일]        ← 권장 (설정 파일을 jar 폴더에서 읽고 씀)
java -jar dist\KLogFilter.jar [로그파일]

로그 파일 경로를 인자로 주면 시작하면서 바로 엽니다. 설정 파일(LogFilter.ini 등)은 실행한 폴더에서 읽고 쓰므로 KLogFilter.bat으로 실행하거나 jar가 있는 폴더에서 실행하세요. 처음 화면에는 버전과 단축키 설명이 보이고, 버전별 변경 이력은 같은 폴더의 CHANGELOG.txt에 있습니다.

직접 빌드

build.bat        → dist\KLogFilter.jar (+ KLogFilter.bat, LogFilterCmd.ini, CHANGELOG.txt)

4. 로그 파일 열기

  • File > Open, File > Recent, 창에 파일을 드래그&드롭, 또는 실행 인자로 엽니다.
  • 지원 형식: adb logcat -v threadtime · time · brief · process · tag (+ year · uid), 커널 로그(<4>[시간] msg), dmesg([시간] msg). 형식을 알 수 없는 줄은 메시지로 그대로 보입니다.
  • Text Encode(그림 3의 ③)가 파일 인코딩과 다르면 바꾼 뒤 다시 여세요.
  • 큰 파일은 줄 위치만 먼저 색인하고 화면에 보이는 부분만 읽으므로 수백 MB도 열 수 있습니다. 진행은 상태 표시줄에 나옵니다.

5. adb로 실시간 수집

  1. 1Font Type 로그 목록 글꼴
  2. 2Font Size · OK 글자 크기 입력 후 OK
  3. 3Text Encode 파일을 열 때의 인코딩 (adb 수집은 항상 UTF-8)
  4. 4Goto 줄 번호를 넣으면 그 줄로 이동
  5. 5Cmd 실행할 adb 명령. 목록은 LogFilterCmd.ini
  6. 6Clear 화면 비우기 (수집 중에만)
  7. 7Run 수집 시작
  8. 8Pause / Resume 화면 갱신만 잠시 멈춤 (기록은 계속)
  9. 9Stop 수집 끝
  10. 10연결 대기 ADB가 끊겨도 기다렸다가 이어서 (12장)
  11. 11Search 메시지 검색어 (7장)
  12. 12▲ 이전 찾기
  13. 13▼ 다음 찾기

수집 순서

  1. Device select(그림 6의 ①~③)에서 OK를 누르면 연결된 장치 목록이 나옵니다. 하나면 자동 선택되고, 여러 개면 목록에서 고릅니다. (offline), (unauthorized)처럼 상태가 붙은 장치는 쓸 수 없습니다.
  2. Cmd에서 adb 명령을 고릅니다(기본 logcat -v threadtime). 실제 실행은 adb [-s 장치] <명령>입니다.
  3. Run을 누르면 출력이 실행 폴더의 LogFilter_날짜_시각.txt에 기록되면서 화면에 바로 나옵니다.
  4. Pause는 화면만 멈추고(Resume하면 밀린 줄이 들어옴), Clear는 화면을 비우며, Stop이 수집을 끝냅니다.
장치가 offline이거나 여러 개인데 고르지 않은 채 Run을 누르면 실행하지 않고 상태 표시줄에 이유를 보여 줍니다. 실행 중 adb가 5초 동안 아무것도 내보내지 않으면 경고가 나옵니다.

모든 필터는 입력하는 즉시 적용되고, 각 줄 왼쪽의 체크를 끄면 그 조건만 잠시 끌 수 있습니다. 여러 단어는 |로 나누며(OR) 대소문자는 구분하지 않습니다.

필터설명
Find / RemoveMessage 기준. .* 토글을 켜면 입력을 정규식으로 봅니다.
Tag Show / Remove로그 목록의 Tag 셀에서 Alt+좌클릭(Show) / Alt+우클릭(Remove)으로 바로 추가할 수 있습니다.
Time12:30, 12:30:15.500, 10-07 12:30, 2026-10-07 12:30 형식. 비우면 제한 없음. 날짜 버튼으로 고르거나, 로그 줄을 오른쪽 클릭해 "이 줄 시각을 Time 시작/끝으로"를 고를 수 있습니다. 날짜 없이 시작이 끝보다 늦으면 자정을 넘는 범위로 봅니다.
  • 입력창에서 Ctrl+Z / Ctrl+Y로 되돌리기·다시 실행.
  • 입력창마다 최근 입력 10개를 기억합니다. ↑/↓로 불러오거나 ▼(Alt+↓) 목록에서 고릅니다. 다음 실행에도 유지됩니다.

7. 하이라이트와 검색

Highlight(그림 6의 ⑪~⑬): 단어를 넣으면 로그 목록에서 그 단어가 배경색으로 표시됩니다(그림 7의 ERROR, connected). 입력창마다 색을 고르고 체크로 켜고 끕니다.

Search(그림 5의 ⑪~⑬): 필터와 별개로 메시지에서 줄을 찾아 선택합니다.

  1. F4(또는 Ctrl+F)로 검색창으로 갑니다. 기존 검색어는 전체 선택되어 바로 바꿔 칠 수 있습니다.
  2. 검색어를 넣고 Enter로 다음, Shift+Enter로 이전 줄을 찾습니다(▲▼ 버튼과 같음). 여러 단어는 |로 나눕니다.
  3. 찾은 줄이 선택되고 검색어는 빨간 글씨로 보입니다(그림 7의 onCreate). 끝에 닿으면 처음부터 이어서 찾습니다.
  4. Esc를 누르면 진행 중인 검색을 멈추고 포커스가 로그 목록으로 돌아갑니다.

9. 장치 통계 (CPU · 메모리 · 온도)

View > 장치 통계 보기(또는 상태 표시줄 오른쪽 클릭)로 통계 창을 엽니다. 숨겨도 측정은 계속됩니다.

기본은 측정 안 함입니다. 창에서 옵션을 정한 뒤 측정 시작을 눌러야 시작되고, 프로그램을 켜거나 창을 열어도 자동으로 시작하지 않습니다.
  1. 1요약 장치 · CPU % · CPU 온도 · 메모리 사용/전체
  2. 2주기 1·2·5·10·30·60초 (측정 중에는 잠김)
  3. 3측정 시간… 계속 / 몇 시간 뒤 자동 멈춤 (그림 10, 측정 중에는 잠김)
  4. 4측정 시간 줄 계속 / 남은 시간 / 측정 완료(시작 ~ 끝)
  5. 5메모리 사용·전체·사용 가능 MB
  6. 6온도 CPU 온도와 센서별 온도 (툴팁에 전체)
  7. 7재부팅 측정 중 감지한 재부팅 횟수와 시각
  8. 8CPU 표시 그래프 선과 코어별 막대
  9. 9코어별 cpu0, cpu1, … 선 (CPU가 켜져 있을 때)
  10. 10메모리 표시 그래프 선과 메모리 줄
  11. 11온도 표시 그래프 선과 온도 줄
  12. 12간격 측정 하나의 가로 폭 1·2·4·8px
  13. 13그래프 측정을 켠 뒤의 전체 기록. 파랑 CPU, 초록 메모리, 주황 온도. 오류 구간은 분홍 띠, 재부팅은 빨간 세로선
  14. 14스크롤 바 구간 이동(마우스 휠도 됨). 맨 오른쪽이면 새 측정을 따라감
  15. 15코어별 CPU 코어마다 막대 (꺼진 코어는 "꺼짐")
  16. 16CPU 상위 프로세스 창이 열려 있는 동안 top으로 읽은 10개
  17. 17측정 시작
  18. 18측정 종료 멈추되 창과 기록은 남김
  19. 19완료 시 자동 저장 끝나면 엑셀 자동 저장
  20. 20엑셀로 저장… (10장)
  21. 21이미지로 복사 창을 클립보드로 (Ctrl+C)
  22. 22이미지 저장… PNG 파일로

측정 순서

  1. Device select에서 장치를 고릅니다(통계도 같은 장치를 봅니다).
  2. ② 주기와 ③ 측정 시간을 정합니다.
  3. ⑰ 측정 시작을 누릅니다. 측정 중에는 ②③이 흐리게 잠깁니다.
  4. ⑱ 측정 종료를 누르거나 정한 시간이 끝나면 멈춥니다. 창은 그대로 남고 설정이 다시 풀립니다.

측정 기록은 최대 20만 회까지 보관하며 넘으면 오래된 것부터 버립니다. 표시 옵션과 주기·측정 시간·자동 저장 설정은 다음 실행에도 유지됩니다.

10. 엑셀 저장

엑셀로 저장…(그림 9의 ⑳)을 누르면 측정을 켠 뒤의 전체 기록이 .xlsx로 저장됩니다. 완료 시 자동 저장(⑲, 기본 켬)이면 정한 측정 시간이 끝나거나 측정 종료를 누를 때 실행 폴더에 DeviceStats_날짜_시각.xlsx로 자동 저장됩니다. 외부 라이브러리 없이 만들며 Excel에서 바로 열립니다.

시트내용
통계측정마다 한 줄: 시각, 경과(초), CPU %, 메모리 %·사용·전체·사용 가능 MB, CPU 온도, cpu0~N %, 센서별 온도, 비고(재부팅 / 오류). 못 읽은 값은 빈 칸
그래프통계 시트의 셀을 참조하는 엑셀 꺾은선 차트 3개 (아래 그림). 셀 값을 고치면 차트도 바뀝니다
메모리 상위전체 기록에서 메모리 최고 점유가 큰 프로세스 5개의 시각별 MB (차트 자료)
상위 프로세스창이 열려 있어 top을 읽은 측정의 CPU 상위 프로세스 (시각 · PID · CPU % · 이름)
메모리 상위 프로세스측정마다 읽은 메모리 상위 10개 (시각 · PID · MB · 이름)
정보프로그램 버전, 장치, 측정 시작·끝, 주기, 측정 시간 설정, 측정·오류·재부팅 횟수, 재부팅 기록, 저장 시각

11. 기록 파일과 분할

  • Run으로 수집한 내용은 실행 폴더의 LogFilter_날짜_시각.txt에 UTF-8로 기록됩니다.
  • 파일이 File > 기록 파일 크기(그림 3의 ④)에서 정한 크기(10·50·100·200·500 MB·1 GB 또는 직접 입력, 기본 100 MB)를 넘으면 이름_2.txt, _3.txt …에 이어서 기록합니다. 줄 중간에서 나누지 않습니다.
  • 수집 중 화면은 여러 파일을 하나로 이어서 보여 주며 필터·검색·북마크도 파일 경계와 무관하게 동작합니다.
  • 나중에 다시 열 때는 파일 하나씩 열립니다(_2, _3은 따로).

12. ADB 연결이 끊겼을 때

연결 대기 체크동작
끔 (기본)케이블이 빠지거나 장치가 재부팅되어 연결이 끊기면 바로 Stop 됩니다. 기록 파일 끝에 -------- ADB device disconnected : logging stopped -------- 줄이 남고 상태 표시줄에 안내가 나옵니다.
켬끊겨도 수집 상태를 유지한 채 다시 연결될 때까지 기다렸다가 같은 화면·같은 기록 파일에 이어서 보여 줍니다. 끊김과 재연결 시점에 표시 줄이 들어가고, 재부팅이면 ======== Device reboot detected … ======== 줄이 북마크와 함께 들어갑니다. Stop으로 기다림을 중단할 수 있습니다.

체크는 아래 바의 연결 대기(그림 5의 ⑩) 또는 File > ADB 연결 대기(그림 3의 ③)에 있으며 설정에 저장됩니다. 네트워크 장치(IP:5555)는 adb 서버가 다시 시작되면 연결이 끊기므로 명령 창에서 adb connect IP:5555로 다시 연결한 뒤 OK를 누르세요.

15. 문제 해결

증상확인할 것
Run을 눌러도 아무것도 안 나옴상태 표시줄의 안내를 보세요. 장치가 offline/unauthorized이거나 여러 장치 중 고르지 않은 경우입니다. OK로 목록을 새로 고치고, 장치에서 USB 디버깅을 허용하세요.
"Waiting for device"가 계속 나옴adb가 장치를 찾지 못하는 상태입니다. Stop 후 adb devices로 확인하고 다시 Run.
수집이 갑자기 Stop 됨ADB 연결이 끊긴 것입니다(기본 동작). 끊겨도 기다리려면 연결 대기를 켜세요.
한글이 깨짐파일을 열 때 Text Encode를 파일 인코딩에 맞추세요. adb 수집은 항상 UTF-8입니다.
장치 통계가 비어 있음통계 창의 측정 시작을 눌렀는지, 장치가 선택되어 있는지 확인하세요. 상위 프로세스 표는 창이 열려 있을 때만 채워집니다.
설정이 저장되지 않음설정은 실행한 폴더에 저장됩니다. KLogFilter.bat으로 실행하거나 jar 폴더에서 실행하세요. 강제 종료는 설정을 저장하지 않을 수 있습니다.
엑셀 차트에 선이 끊김그 측정에서 값을 못 읽었거나(오류·꺼진 코어) 그 프로세스가 상위 10개에 들지 않은 구간입니다. 정상입니다.
