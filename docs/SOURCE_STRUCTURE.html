KLogFilter 소스 구조 및 동작 흐름

작성일 2026-10-02 · 대상 버전 LogFilter Version 1.8 · 기준 소스 github.com/nod435/KLogFilter fd5e19f + 로컬 변경분(1.1)

Android logcat 로그를 보면서 필터링하는 Java Swing 데스크톱 툴의 클래스 구성, 실행 흐름, 문제점과 최적화 방향을 정리한 문서입니다. 동작 흐름은 시퀀스 다이어그램으로 표현했습니다.

1개요

  • 입력: 저장된 로그 파일(Open, Recent, 드래그&드롭, 실행 인자)을 읽거나, adb logcat 출력을 실시간으로 받습니다.
  • 기능: 워드/태그/PID/TID/레벨 필터, 하이라이트, 북마크, 에러/북마크 인디케이터, 컬럼 숨김, 클립보드 복사
  • 빌드 환경: Eclipse Java 프로젝트이며 .classpath에는 JavaSE-1.6이 설정되어 있습니다. 현재는 JDK 8(Zulu 1.8.0_382)로 빌드했습니다.
  • 패키지: default 패키지만 사용하고, 외부 라이브러리 의존성은 없습니다.

3.2 구조적 특징

  • God class: LogFilterMain이 UI, I/O, 필터링, 설정을 모두 맡고 있습니다(전체 코드의 약 50%).
  • 양방향 결합: LogTable과 IndicatorPanel이 LogFilterMain의 필드(m_scrollVBar, m_tbLogTable, m_nChangedFilter)에 직접 접근합니다.
  • 필터 상태가 뷰에 있음: 필터 문자열은 LogTable 필드로 보관되고, 실제 판정은 LogFilterMain.check*Filter()가 getter를 통해 읽습니다.
  • 전역 static 상태: LogColor의 색상과 LogFilterTableModel.ColWidth가 모두 public static입니다.

4동작 흐름 (시퀀스 다이어그램)

각 다이어그램의 번호는 호출 순서입니다. 다이어그램이 화면보다 넓으면 좌우로 스크롤해서 볼 수 있습니다.

호출 반환 스레드 생성 · 비동기 신호 사용자 백그라운드 스레드 외부 프로세스 · 파일 빨간 글씨 = 7장의 문제점과 관련

4.1 앱 시작

  • 필터 스레드는 생성자 중간에 시작되며, 그 뒤로 앱이 끝날 때까지 FILTER_LOCK.wait()로 신호를 기다립니다.
  • 설정은 setVisible(true) 다음에 로드됩니다. 필터 텍스트를 넣는 순간 DocumentListener가 동작해 저장된 필터가 바로 적용됩니다.
  • 메뉴바는 생성자가 끝난 뒤 main()에서 붙입니다.

4.2 로그 파일 열기

  • 네 가지 진입 경로가 모두 parseFile(File) 하나로 모입니다. 단, Recent 목록에 추가되는 경로는 Open 하나뿐입니다.
  • 문자 인코딩은 Encode 콤보 값(UTF-8 / Local)에 따라 정해집니다.

4.3 logcat 실시간 수집

  • 프로세스 스레드와 파일 감시 스레드는 파일을 사이에 두고 동시에 동작합니다(par 구간).
  • Pause는 화면 반영만 멈추고 파일 기록은 계속합니다. Clear는 읽어 둔 데이터만 지우고 파일 읽기 위치는 그대로입니다.
  • 장치를 선택하면 명령에 -s <serial>이 붙습니다. adb는 PATH에서 찾습니다.

4.4 필터 재계산

  • 필터 문자열은 |로 나눈 OR 조건이며, 대소문자를 무시하는 부분 일치(contains)로 판정합니다.
  • 대상 필드는 Find/Remove가 Message, Show/Remove Tag가 Tag, Pid가 Pid, Tid가 Thread입니다. 레벨은 m_nFilterLogLV 비트 마스크로 판정합니다.
  • 재계산 중에 새 변경이 들어오면 STATUS_CHANGE를 보고 루프를 중단한 뒤 처음부터 다시 계산합니다.

4.5 셀 렌더링

  • 스크롤하거나 갱신할 때마다 보이는 모든 셀에 문자열 치환과 HTML 생성이 반복됩니다. 대용량 로그에서 가장 큰 성능 비용입니다(P1).
  • 원래는 HTML 이스케이프가 없어서 메시지 안의 <init> 같은 텍스트가 사라졌습니다(B3). 2026-10-04에 일치 구간을 먼저 계산하고 HTML을 한 번에 만드는 방식으로 고쳤습니다.

5클래스별 상세

5.1 전체 클래스 관계도

실제로 쓰이는 클래스 13개의 관계를 UML 표기로 그렸습니다. 상속하는 Swing 클래스는 각 상자 위쪽에 extends …로 적었고, 상자 아래쪽 글씨는 LogFilterMain이 그 객체를 담는 필드 이름입니다. 모든 클래스가 쓰는 T와, LogFilterMain이 설정을 로드/저장할 때 쓰는 LogColor로 향하는 선은 생략했습니다.

상속 (extends) 구현 (implements) 생성·소유 (필드) 참조 사용·생성 (의존) 내부 클래스 핵심 클래스 인터페이스 내부 클래스
