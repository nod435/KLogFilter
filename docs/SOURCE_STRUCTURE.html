3.2 구조적 특징

  • 역할 분리(S1): LogFilterMain은 화면만 맡고, 데이터·필터는 FilterEngine, 입력은 LogSource, 설정은 AppConfig가 맡습니다. FilterEngine과 LogSource는 Swing을 직접 쓰지 않고 Listener로만 알립니다.
  • 스레드 경계: Listener 알림은 어느 스레드에서든 올 수 있으므로, LogFilterMain이 runOnEdt()로 EDT에서 화면에 반영합니다.
  • 필터 상태 위치(S5): 필터 조건(문자열과 토큰)은 FilterEngine이 가집니다. 표시 설정인 하이라이트만 LogTable에 남았습니다.
  • 남은 결합: LogTable과 IndicatorPanel은 여전히 LogFilterMain의 필드(m_scrollVBar, m_tbLogTable, m_engine)를 직접 참조합니다. LogColor와 LogFilterTableModel.ColWidth는 public static입니다.

4동작 흐름 (시퀀스 다이어그램)

각 다이어그램의 번호는 호출 순서입니다. 다이어그램이 화면보다 넓으면 좌우로 스크롤해서 볼 수 있습니다.

호출 반환 스레드 생성 · 비동기 신호 사용자 백그라운드 스레드 외부 프로세스 · 파일 빨간 글씨 = 7장의 문제점과 관련

4.1 앱 시작

  • LogFilterMain은 생성자에서 FilterEngine·LogCatParser·LogSource를 만들고, 재필터 스레드는 앱이 끝날 때까지 요청을 기다립니다.
  • 설정은 setVisible(true) 다음에 로드됩니다. 필터 텍스트를 넣는 순간 DocumentListener가 동작해 저장된 필터가 바로 적용됩니다.
  • 메뉴바는 생성자가 끝난 뒤 main()에서 붙입니다.

4.2 로그 파일 열기

  • 네 가지 진입 경로가 모두 LogFilterMain.parseFile(File) → LogSource.parseFile()로 모입니다. 단, Recent 목록에 추가되는 경로는 Open 하나뿐입니다.
  • 문자 인코딩은 Encode 콤보 값(UTF-8 / Local)에 따라 정해집니다.

4.3 logcat 실시간 수집

  • 프로세스 스레드와 파일 감시 스레드는 파일을 사이에 두고 동시에 동작합니다(par 구간).
  • Pause는 화면 반영만 멈추고 파일 기록은 계속합니다. Clear는 읽어 둔 데이터만 지우고 파일 읽기 위치는 그대로입니다.
  • 장치를 선택하면 명령에 -s <serial>이 붙습니다. adb는 PATH에서 찾습니다.

4.4 필터 재계산

  • 필터 문자열은 |로 나눈 OR 조건이며, 대소문자를 무시하는 부분 일치(contains)로 판정합니다.
  • 대상 필드는 Find/Remove가 Message, Show/Remove Tag가 Tag, Pid가 Pid, Tid가 Thread입니다. 레벨은 m_nFilterLogLV 비트 마스크로 판정합니다.
  • 재계산 중에 새 변경이 들어오면 STATUS_CHANGE를 보고 루프를 중단한 뒤 처음부터 다시 계산합니다.

4.5 셀 렌더링

  • 렌더러는 일치하는 토큰이 없으면 HTML을 만들지 않고 바로 반환합니다(P1). Find/Tag 토큰은 FilterEngine, 하이라이트 토큰은 LogTable에서 읽습니다.
  • 원래는 HTML 이스케이프가 없어서 메시지 안의 <init> 같은 텍스트가 사라졌습니다(B3). 2026-10-04에 일치 구간을 먼저 계산하고 HTML을 한 번에 만드는 방식으로 고쳤습니다.

5.3 클래스별 설명

LogFilterMain (화면)

  • 화면을 만들고 사용자 입력을 FilterEngine·LogSource에 전달합니다. 자신은 데이터나 스레드를 갖지 않습니다.
  • FilterEngine.Listener와 LogSource.Listener를 구현해 알림을 받고, runOnEdt()로 EDT에서 refreshTable()·상태 표시·버튼 상태를 바꿉니다.
  • 설정은 시작할 때 AppConfig.load() → applyConfig(), 종료할 때 saveConfig() → AppConfig.save()로 주고받습니다.
  • 필터 입력은 250ms 디바운스 후 FilterEngine.requestFilter(), 하이라이트는 LogTable에 넣고 다시 그리기만 합니다.

FilterEngine (데이터 · 필터)

  • 전체/필터 결과 목록과 북마크·에러 위치 맵, 필터 조건 6종(문자열 + 소문자 토큰), 레벨 마스크, 북마크만/에러만 보기 상태를 가집니다.
  • addNext()는 줄 번호를 (개수 + 1)로 정해 추가하므로, 번호와 목록 위치가 항상 맞습니다.
  • 재필터 스레드는 요청 플래그(m_bFilterRequested)와 wait/notify로 동작합니다. 새 목록을 채운 뒤 교체하고 onDataChanged(SELECT_LAST)로 알립니다. 진행 중에 조건이 바뀌면(markChanged()) 중단합니다.
  • getView()는 지금 표시할 목록과 맵을 LOCK 없이 돌려줍니다(EDT가 재필터 동안 멈추지 않도록).

LogSource (입력)

  • 파일: parseFile()이 ParseFile 스레드에서 읽어 addNext()하고, 끝나면 재필터를 요청합니다. 새 파일을 열면 세대 번호가 바뀌어 이전 스레드는 멈춥니다.
  • adb: startProcess()가 AdbProcess 스레드에서 adb 출력(stderr 포함)을 기록 파일에 쓰고, WatchFile 스레드가 50ms마다 그 파일을 이어 읽어 추가합니다. Stop 직후 Run 해도 이전 스레드가 새 프로세스를 건드리지 않습니다.
  • 장치 목록: listDevices()가 AdbDevices 스레드에서 adb devices를 실행하고 onDevices()로 알립니다.

AppConfig (설정)

  • ini 파일 이름과 키 상수, 창 크기 기본값을 모아 둡니다. LogFilter.ini 값은 필드로, 색상은 LogColor에, 명령 목록은 List로 읽습니다.
  • 키가 없거나 값이 잘못되면 그 키만 기본값을 씁니다(intOf/hexOf). 스트림은 try-with-resources로 닫습니다.

LogTable · LogFilterTableModel · IndicatorPanel

  • LogTable: 하이라이트(표시 설정)만 직접 가지고, Find/Tag 토큰은 FilterEngine에서 읽습니다. Alt+클릭 태그 추가/제거도 FilterEngine에 반영합니다. F2/F3은 표시 중인 북마크 위치를 정렬 집합(TreeSet)에서 찾습니다(S6).
  • LogCellRenderer: 일치하는 토큰이 없으면 원문을 그대로 쓰고, 있을 때만 HTML(이스케이프 포함)을 만듭니다. Font/Color는 값이 바뀔 때만 새로 만듭니다.
  • LogFilterTableModel: FilterEngine의 목록을 참조로 들고, EDT에서 syncRowCount()로 알린 행 수까지만 보여줍니다.
  • IndicatorPanel: 북마크(파랑)·에러(빨강) 위치와 화면 범위를 그리고, 클릭/드래그로 이동합니다. 재필터 중에는 막대 그리기를 건너뜁니다.

LogCatParser · LogInfo · FilterToken · 기타

  • LogCatParser: 줄 첫 글자로 후보 형식을 좁힌 뒤 형식을 판별합니다(2026-10-06 확장, B13). 가장 흔한 threadtime 기본형은 정규식 없이 직접 나누고(빠른 경로), 나머지는 미리 컴파일한 정규식으로 처리합니다. 어느 형식에도 맞지 않으면 줄 전체를 메시지로 씁니다.
    형식 (adb logcat -v …)예
    threadtime04-20 12:06:02.125 146 179 D BatteryService: update start
    time04-17 09:01:18.910 D/LightsService( 139): BKL : 106
    + year2026-04-20 12:06:02.125 … (위 두 형식 앞에 연도)
    + uid04-20 12:06:02.125 1000 146 179 D Tag: msg / D/Tag( 1000: 139): msg
    briefD/LightsService( 139): BKL : 106
    processD( 139) BKL : 106 (LightsService)

    레벨 A(Assert)는 Fatal로 다룹니다. threadtime 태그는 : 앞까지에서 오른쪽 공백을 뺀 값이고, 메시지 앞 공백 한 칸도 뺍니다.
  • LogInfo: 문자열 필드 9개와 줄 번호·레벨 int, 색상, 북마크 여부를 가집니다.
  • FilterToken: "a|B" → {"a","b"} 분리와, 새 문자열을 만들지 않는 대소문자 무시 부분 일치 판정.
  • RecentFileMenu(GPL v2), LogColor(static 색상), INotiEvent(이벤트 0~3), T(디버그 출력, 항상 켜짐)는 역할이 그대로입니다.
